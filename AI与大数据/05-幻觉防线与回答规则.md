# 05 幻觉防线与回答规则

> 本文件定义"什么算一个合格回答"。AI 助手在本项目内必须逐条遵守。

## 1. 四道闸门

| 闸门 | 位置 | 机制 |
| --- | --- | --- |
| 语料闸门 | `github_source.py` | 只收白名单许可证、固定 commit，杜绝"凭印象引用仓库" |
| 检索闸门 | `retrieve.py` | 覆盖率 < 34% 直接拒答，不进模型 |
| 生成闸门 | `llm.py` / `SYSTEM_PROMPT` | 只允许用 context，强制引用 |
| 落盘闸门 | `pipeline.py` | 代码块 AST 自检，引用可回溯 |

## 2. 回答格式（硬性）

1. 每个事实后必须有 `[仓库:路径:起始行-结束行]`；
2. 引用必须能在当前索引的 chunk 中找到（`citation` 与 `chunk_id` 完全一致）；
3. 语料不足时，第一句写「语料中未检索到」并说明缺什么；
4. 不输出未在语料出现的函数名、参数、版本号、URL、许可证；
5. 不声称运行过未运行的命令，不声称测试通过但实际未跑。

## 3. 拒答规则

满足任一条件即拒答：

- 查询英文关键词覆盖率 < 0.34；
- 零命中；
- 问题为空 / 只有标点或停用词；
- 问题超出已采集仓库范围（例：Rust、HuggingFace）。

拒答必须包含：当前语料仓库列表、覆盖率数值、下一步建议（换英文关键词 / 扩充语料）。

## 4. 系统提示词（`config.SYSTEM_PROMPT` 摘要）

```text
1. 只能使用 <context> 中的内容作答；没有的信息直说"语料中未检索到"。
2. 每个结论后标注来源 [仓库/路径:起止行]。
3. 不得编造函数名、参数、版本号、URL、许可证；不确定写"不确定"。
4. 代码必须来自 context；不要臆造未出现的 API。
5. 问题超出语料范围时，先说明边界，再给最接近的事实。
```

提示词与代码同源（`rag/config.py`），文档不另抄一份"看起来差不多"的版本。

## 5. 不确定性分级

| 级别 | 含义 | 允许表述 |
| --- | --- | --- |
| A 直接证据 | 语料原文明确写出 | "根据 [引用]，…" |
| B 组合推断 | 多段语料可拼出 | "由 [引用1][引用2] 可推断…（推断，非原文）" |
| C 语料缺失 | 检索不到 | "语料中未检索到；已知语料仅覆盖 …" |
| D 未验证 | 文档/命令未跑 | "未在本机验证，不可作为结论" |

禁止把 B 写成 A，禁止把 C 补成"通常来说"。

## 6. 引用与可回溯

- 索引中 `chunk_id` 格式：`仓库:路径:起始行-结束行`；
- URL 由 `commit_sha + path + #L起-L止` 拼出，直接打开 GitHub 原文；
- 审计方法：

```powershell
python -m rag.cli search "你的问题" --top-k 6   # 看命中与行号
python -m rag.cli ask "你的问题" --json          # 看 citations 与 sources
```

## 7. 文档自身的反幻觉

- 环境/版本/commit 只写在 `01-事实基准.md`，且注明核实命令；
- 易漂移的数字（chunks、vocab、API 配额）**不写死**，改为"用 stats 查询"；
- 每条命令都在本机执行过，输出进 `docs/05-验证记录.md`；
- 发现文档与代码冲突，以代码与实测为准，立即修正文档。

## 8. 人工升级（Escalation）

以下情况必须停下来问人，不得自行决定：

1. 要新增/替换语料仓库（涉及许可证）；
2. 要改 `ALLOWED_LICENSES` 或许可证策略；
3. 要接入新的模型供应商或计费接口；
4. 要 force push、改写历史、删除分支；
5. 要提交真实凭据（API Key、Token、SSH 私钥）。

## 9. 自查清单（回答前）

- [ ] 每个结论都有引用？
- [ ] 引用能在索引中定位？
- [ ] 没有编造版本号/URL？
- [ ] 越界问题已拒答？
- [ ] 抽取式模式已标注"未调用大模型"？
- [ ] 代码产物通过 `ast.parse` 或已如实标注失败？
