# 03 数据源与语料许可

## 1. 语料仓库（固定 commit）

| 仓库 | 许可证 | commit | 角色 |
| --- | --- | --- | --- |
| pallets/flask | BSD-3-Clause | `49943b5a9441…`（完整 sha 见下） | Web 框架：路由、蓝图、会话 |
| psf/requests | Apache-2.0 | `3c7baaa05ab4…` | HTTP 客户端：Session、timeout、适配器 |
| tiangolo/fastapi | MIT | `a1b3be01aadc…` | 依赖注入、参数校验示例 |

完整 sha：

```text
pallets/flask     49943b5a94413a530761350f04e896f76e8d620e
psf/requests      3c7baaa05ab4aa49cc819ce3a819d260de19c157
tiangolo/fastapi  a1b3be01aadc61c67edc09eed4f6cc1fcc3d3b8f
```

许可证不是抄来的：`fetch_repo()` 调用 GitHub API 读取 `license.spdx_id`，
与 `config.DEFAULT_REPOS[*].expected_license` 比对，不一致直接失败；
不在 `ALLOWED_LICENSES` 白名单内整仓拒收。

## 2. 为什么是这三个仓库

- 全部为 OSI 认可许可证，可安全引用；
- 覆盖"路由注册 / HTTP 超时 / 依赖注入"三类典型代码问答；
- 体量适中（每仓入库 6~10 个文件），索引可在秒级重建。

它们**不代表**对 GitHub 全站的覆盖；语料边界即上表，超出即拒答。

## 3. 采集链路（受本机网络事实约束）

```text
GitHub API (/repos, /branches)  ->  许可证、默认分支、HEAD sha、仓库元数据
jsDelivr 镜像 (data.jsdelivr.com) ->  按 sha 列出文件树
jsDelivr CDN (cdn.jsdelivr.net) ->   按 sha 读取文件内容
```

原因（见 `01-事实基准.md`）：

| 端点 | 实测 | 结论 |
| --- | --- | --- |
| `raw.githubusercontent.com` | 30s 超时 | 不可用 |
| `codeload.github.com` | 740KB/44s | 太慢 |
| `api.github.com` | 2s，60 次/小时 | 仅用于元数据 |
| `cdn.jsdelivr.net` | 67KB/1.5s，不限流 | 用于文件内容 |

这不是"换个来源"：jsDelivr 镜像的就是 GitHub 仓库同一 commit 的文件，
引用 URL 仍指向 `github.com/<repo>/blob/<sha>/<path>`，可逐字核对。

## 4. 选文件规则

1. 仅 `.py` / `.md`，单文件 ≤ 90KB，每仓 ≤ 10 个，总量 ≤ 200K 字符；
2. 排除 `tests/`、`.github/`、`certs/`、`docs/`、`vendor/`、`node_modules/`；
3. 打分优先 `src/`、`fastapi/`、`docs_src/`、`examples/`；
4. README 每仓最多 1 个，`docs_src` 最多 3 个，避免文档压过源码；
5. 文件按固定 commit 抓取，重建索引不会漂移到新版本。

## 5. 语料文件结构

`data/corpus/<owner>__<repo>.json`：

```json
{
  "full_name": "pallets/flask",
  "license": "BSD-3-Clause",
  "commit_sha": "49943b5a…",
  "default_branch": "main",
  "fetched_at": "2026-11-17T22:34:19+08:00",
  "content_source": "cdn.jsdelivr.net (GitHub 仓库镜像，commit 固定)",
  "files": [
    {"path": "src/flask/app.py", "size": 67780, "text": "...", "url": "https://github.com/…/blob/<sha>/src/flask/app.py"}
  ]
}
```

`data/` 被 `.gitignore` 忽略：语料可再抓，不入库，避免仓库膨胀与许可证二次分发风险。

## 6. 更新语料

```powershell
# 重新抓取（沿用已记录的 commit 与许可证）
python -m rag.cli fetch --refresh

# 仅重抓某仓
python -m rag.cli fetch --repos pallets/flask --refresh

# 重建索引 + 验收
python -m rag.cli index
python scripts/evaluate.py
```

若要升级到上游新 commit，需要联网调用 GitHub API 重新取 sha，并同步更新
`01-事实基准.md`、`THIRD_PARTY_NOTICES.md` 与本文件。

## 7. 许可与合规

- 代码：MIT；文档：CC BY 4.0；第三方片段：遵循上游许可证（见 `THIRD_PARTY_NOTICES.md`）。
- 引用只到"片段级"，不复制整仓；生成物头部标注来源与 commit。
- 若上游许可证变更，以 `fetch` 时的 API 返回为准，不匹配即拒收。
